# Before-event checklist

A checklist catches avoidable failures; it cannot guarantee compliance or performance. Adapt this to the current game manual, inspection rules, and your team's procedures.

## Robot and pit

* [ ] Current official rules and inspection requirements reviewed
* [ ] Mechanical fasteners and moving systems checked
* [ ] Wiring reviewed and issues recorded
* [ ] Driver controls and emergency procedures understood
* [ ] Batteries and charging handled per applicable safety procedures
* [ ] Spare parts, tools, and labeled storage ready
* [ ] Robot code backed up and known-good version tagged
* [ ] Known issues and mitigations documented

## People and operations

* [ ] Drive team knows field communication and handoff process
* [ ] Pit roles and supervision assigned
* [ ] Safety brief completed
* [ ] Event schedule, transport, and contact plan distributed
* [ ] Outreach/demo materials prepared if needed

## Post-event

Capture the failures, fixes, and surprises while they are still fresh. Keep a brief **what worked / what didn't / what we'll change** retrospective.

Official rules are available via [FIRST](https://www.firstinspires.org/).

## Rehearse one recovery

Use a practice session to reproduce a routine software recovery under supervision: find the last known-good commit, identify the build toolchain and locate configuration notes. Keep an offline copy of essential instructions. Use [the maintained program pages](../resource-library/kentucky-teams-season.md) for current event and inspection information.
